# 考察方向：均衡（balanced）

本组问题不限定单一考察方向（`task.focus = balanced`），在业务场景、实现细节、架构设计与复盘决策之间按证据自由选择，不偏向某一类。

## 出题要求

- 以 `profile` 与 `anchors` 中最有面试价值的证据为准，哪类证据充分就多出哪类卡。
- 不设优先维度，某个考察维度没有足够证据时允许完全不出现。
- 最终问题卡应体现候选人真实经历中的重点，而不是各维度的平均分配。

## 追问链

每张卡写 4 条追问，按 L1 → L2 → L3 递进，固定分配：**1 条 L1、1 条 L2、2 条 L3**。证据特别充分时可以写 5 条，但其中 L3 仍然至少 2 条；不要为了凑数写 3 条。固定分配是为了保证 L3 占比，不需要自己计算比例。

- `L1` 澄清实现细节：具体怎么做、边界条件、数据从哪来。
- `L2` 决策权衡：为什么选这个方案、替代方案是什么、代价是什么。
- `L3` 归因 / 反事实：结果里个人贡献占多少、指标怎么归因、条件变化会怎样、如果重做会改什么。

追问必须能顺着主问题自然问出来，不要跳到无关话题；同一张卡内的追问不要重复同一个点，否则合并去重后 L3 数量会被动减少。

## 维度倾向

- 不设优先维度，`dimension` 按每张卡实际考察的内容选取，不做占比要求。

## 禁止事项

- 不要为了凑齐所有方向或所有维度而刻意凑题。
- 不要把问题停留在泛泛的经验总结上，必须关联具体项目经历。

没有足够证据时，宁可少出题，也不要编造。
