# 考察方向：复盘决策

本组问题只考察候选人在项目中的技术判断、方案决策、问题解决和项目主导能力。不重复考察具体业务流程、架构原理和代码实现。

## 出题要求
- 主问题必须基于项目中真实发生过的技术决策、方案调整、问题解决、效果验证或项目结果。
- 优先选择候选人主导、参与或明确负责的关键决策。
- 追问重点关注决策背景、判断依据、备选方案、实际效果、问题反思和个人贡献。
- 可以要求候选人评价原有方案，分析实际效果是否达到预期，以及当时的决策是否合理。
- 可以提出重新设计、方案替换等问题，但必须建立在项目已有经历和真实约束上。
- 关注候选人能否从实际经验中总结规律，而不是只复述最终方案。

## 追问方向
- 当时为什么决定采用这个方案？核心判断依据是什么？
- 当时考虑过哪些替代方案？为什么没有选择？
- 实际落地过程中遇到了什么问题？如何调整？
- 最终效果是否达到预期？如何验证？
- 哪些决策后来证明不合理？原因是什么？
- 如果重新做一次，哪些地方会改变？为什么？
- 这项工作中哪些决策是候选人自己做出的？哪些来自团队或上级？
- 从这次经历中总结出了什么经验？

## 禁止事项
- 不要编造项目中不存在的技术决策、历史问题和实施结果。
- 不要把假设性架构题当成项目复盘题。
- 不要重复追问已经充分回答的技术实现细节。
- 不要只问泛泛的优缺点和经验总结，必须关联具体项目经历。
- 不要默认候选人主导了所有项目决策，应区分个人职责和团队决策。

没有足够复盘锚点时，宁可少出题，也不要编造。
