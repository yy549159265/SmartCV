# 场景：综合面试

本次是**综合面试**（`task.kind = theme`）。你会收到一个主题（`task.theme`），只围绕该主题出 1~2 张卡。

综合面试不适用考察方向规则：`task.focus` 恒为 `balanced`，以「场景」与「追问链」两节的规则为准。

## 主题侧重点

- **求职动机**：为什么离开上一段经历、为什么选择这个方向 / 这类团队。要能从简历经历里找到动机的自洽性，不逼问个人隐私。
- **职业规划**：未来 1~3 年想成为什么样的工程师、想补什么能力、与目标岗位的匹配度。追问要落到具体行动，不接受空泛口号。
- **薪资期望**：只问期望区间与依据、可接受的弹性。不要追问当前薪资明细、家庭情况等隐私。
- **稳定性**：离职原因、空窗期、频繁变动的解释、到岗时间。语气保持中立，不做道德评判。
- **项目真实性**：挑画像里最亮的结果或最含糊的表述，核对数据口径、个人贡献与细节。必须优先引用 `<anchors>` 里的真实锚点。

## 场景规则

- 每张卡的 `projectId` 留空。
- `dimension` 选用与当前主题对应的维度。
- `anchorId` 从 `anchors` 里选最匹配的 `id`：真实性主题必须尽量引用，动机类问题可以留空。
- 每个主题只出 1~2 张卡，围绕主题内最有验证价值的内容，不要凑题；两张卡必须考察不同内容，不能只是换一种问法。
- 简历或锚点里没有足够依据时，可以只出一张，不要编造经历、数字或动机。
- 综合面试没有深度追问模式，`task.follow_depth` 恒为 `none`。

## 追问链

综合面试不适用考察方向规则，追问链按下述要求执行：

- 每张卡写 4 条追问，按 L1 → L2 → L3 递进，固定分配 **1 条 L1、1 条 L2、2 条 L3**；证据特别充分时可写 5 条，但 L3 仍至少 2 条，不要只写 3 条。
- `L1` 澄清事实与细节：具体发生了什么、时间与角色、涉及哪些人和环节。
- `L2` 决策与取舍：为什么这样选择、考虑过哪些替代方案、代价是什么。
- `L3` 归因与反思：结果里个人贡献占多少、如何验证、如果重来会改什么。
- 追问必须顺着主问题自然问出来，同一张卡内不要重复同一个点。
- 题目本身不得编造经历或数字；参考答案由进入清单后的答案 Agent 单独生成。
