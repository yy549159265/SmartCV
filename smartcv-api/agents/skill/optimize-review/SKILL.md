# 审查目标

把诊断 agent 给出的 x 条诊断，筛成 y 条确实需要、也确实可以执行的修改。

判定结果和理由会直接展示给用户，也会作为后续修改的唯一依据。所以每一条诊断都必须审查，不能跳过不审。

# 判定为「需要修改」的条件

以下条件**全部满足**才判 change：

1. 诊断指向简历里已经存在的一段文字（坐标和原文片段都能对上）。
2. 问题属实：该位置当前文字确实存在诊断所说的问题。
3. 修改可以只靠「替换这段文字」完成，不需要增删章节/内容行、调整顺序、改排版或图片。
4. 建议只使用简历、JD、用户回答里已有的事实，不要求编造数字、技术或经历。
5. 改完有实际收益：表达更准确、更贴合 JD、消除歧义或重复，而不是为了改而改。

# 判定为「不需要修改」的情况

出现以下任一情况判 skip：

- 结构类诊断：增删章节/内容行、调整顺序、排版、图片等，无法只替换文字。
- 诊断没有可用的坐标或原文片段。
- 诊断引用的原文与该位置当前文字对不上（诊断指错了位置）。
- 修改需要简历里没有的事实或数据。
- 与另一条诊断重复，或改完会和上下文冲突。
- 只是个人风格偏好，改动没有实际收益。

# 理由怎么写

- **change**：一句话说明为什么这条必须改、改完解决什么问题。
- **skip**：一句话说明为什么不需要改或改不了，要指出具体原因，例如「需要新增一段项目经历，无法只替换文字」。

理由要具体到这条诊断，不要写「不符合要求」「建议优化」这类空话。

# 审查顺序

1. 先把全部 x 条诊断逐条审查完，再开始修改；没审完不能执行任何修改。
2. 一次回复可以连续调用多个 `review_diagnosis`，不要一次只审一条。
3. 每条诊断只审一次；判定后不要反复改判。
4. 审查阶段不生成最终文字，只判断改不改、为什么。

# 边界

- 本技能只负责判定，不负责改写文字。
- 不修改简历、不调用 `patch_content`。
- 位置编号的含义见 `coordinate` 技能，本技能不重复。
